# Навык: утренний отчёт PO

> Роль: **дежурный по утру**. Собираешь вчера и сегодня в одну картину: что сделано,
> какие выводы, куда идти, кому что отправить, что проверить у команды, какие риски
> висят на целях. Планнер не меняешь — предлагаешь, PO подтверждает.

Срабатывает на `/morning`, слово `morning`, «план на сегодня», «утренний отчёт»,
«что на сегодня», «ретро за вчера». Аргументы не нужны; `--date ГГГГ-ММ-ДД` — отчёт
за другой день (для проверки).

## Границы

- **Источники — только эти**: Backlog.md (`backlog … --json` в терминале, при его
  отсутствии `mcp__backlog__*`), календарь через `tools/calendar-today/today.py`,
  прошлые отчёты в `GROUND/PULSE/morning/`, последний отчёт спринта в
  `GROUND/RESULTS/*sprint-report*.md`, заметки `GROUND/PULSE/*` с датой вчера.
  Чего нет — блок помечается `[НЕТ ДАННЫХ: …]` с причиной. Не выдумывать.
- **Не читает чаты и транскрипты** — это `/mts-link-sync`, `/link-radar`,
  `/daily-review`. В отчёт идут только их готовые заметки в PULSE.
- **Не пишет в Backlog.md** в ходе отчёта. Единственная запись — файл отчёта в
  `GROUND/PULSE/morning/` (дневник, не планнер).
- **Не пересказывает доску.** В отчёт — то, что меняет день; остальное числом.

## Модель данных

| Сущность | В Backlog.md | Поле/метка |
|---|---|---|
| Цель квартала (Objective) | milestone `m-N` | `milestone list` |
| Ключевой результат (KR) | задача `type: okr` | `milestone` — привязка к цели |
| Задача PO | `type: potask`, `okr-kind:task` (или без `okr-kind`) | `dueDate`, `assignees`, `okr-kr:<id>` |
| Договорённость | `type: potask`, `okr-kind:control` | те же |
| Риск | `type: potask`, `okr-kind:risk` | `assignees` пусто = без владельца |
| Требование (БФТ) | `type: bft` | статус = стадия |
| История спринта | `type: story`, метки `sprint:<id>`, `team:<имя>`, `okr-kr:<id>`, `sprint-result:<…>` | комментарии `[Факт] [Блокатор] [След. шаг]` |
| Дата закрытия/правки | `updatedAt`, `createdAt` (только в `--json`) | |

## Шаг 1 — сбор (ровно так, не больше)

`today` = сегодня (из контекста; нет — один вызов `date +%F`), `yesterday` =
предыдущий календарный день. Дальше, в терминале (cwd — корень воркспейса):

```bash
backlog task list --json                     # ВСЕ задачи: статус, тип, метки, due, updatedAt, assignees
backlog milestone list --plain               # цели и прогресс
ls GROUND/PULSE/morning/ 2>/dev/null | tail -2          # прошлый отчёт → дата дельты
ls -t GROUND/RESULTS/ | grep sprint-report | grep '\.md$' | head -1   # последний отчёт спринта
ls GROUND/PULSE/summaries GROUND/PULSE/radar GROUND/PULSE/daybook 2>/dev/null | grep "$yesterday"
python3 <poh-morning-status>/tools/calendar-today/today.py --date $today   # созвоны сегодня
python3 <poh-morning-status>/tools/calendar-today/today.py --date $yesterday --json   # Activity за вчера
```

`<poh-morning-status>` — чекаут репозитория (на этой машине
`/Users/aleksishmanov/projects/mts-org/poh-morning-status`). Один `--json` даёт всё
для классификации — семь узких вызовов `task_list` не нужны. Терминала нет →
запасной путь: `mcp__backlog__task_list` по типам и меткам (без `updatedAt` блок
«сделано за вчера» помечается `[НЕТ ДАННЫХ: нет дат правок]`).

Затем прочитать: прошлый отчёт (`GROUND/PULSE/morning/<prev>.md`, только раздел
«Статус по командам»), шапку последнего отчёта спринта (frontmatter + «Итог» +
«Ключевые риски»), найденные заметки PULSE за вчера.

`backlog task <id> --json` — только для: договорённостей ближайших 7 дней (нужны
описание/AC под «что проверить» и «how-to-demo») и задач на сегодня («кому что
отправить»). Не больше 10 штук. Риски, KR, БФТ — из списка.

Бюджет ≈ 12–15 вызовов. Больше — отчёт собирается не по навыку.

## Шаг 2 — классификация

- **Ретро = Tasks и Activity, каждая со своей заметкой.** Счётчики план/факт в
  заголовке: план — строки «Задачи» прошлого отчёта (`GROUND/PULSE/morning/<prev>.md`),
  факт по `--json`: `Done` → сделано; открыт, `dueDate` сдвинут → перенесено; открыт,
  срок прошёл → сорвано. Прошлого отчёта нет → «план: нет отчёта».
  Всё сделанное за вчера — строки `tasks` в retro.json: закрытые задачи (`Done`,
  `updatedAt` = вчера) с `id`; заведённые вчера (`createdAt` = вчера) и прочие
  результаты — строки без `id`. У каждой — `note` (markdown, что именно сделано) и
  `source`. Созвоны — `activity` с `summary` (markdown-итог встречи, только по данным:
  повестка/описание события, заметки PULSE; нет — пустая строка). Таблиц по ретро нет.
- **Задачи сегодня** — `okr-kind:task` (и без kind) с `dueDate ≤ today`, открытые;
  просроченные — с дельтой в днях. «Кому / что отправить» — из заголовка и описания
  (`Ишманов + Бордюг: отправить смету` → кому: Бордюг, что: смета за август). Нет
  адресата — «—», не додумывать.
- **Ближайшие договорённости** — `okr-kind:control`, открытые, `dueDate` в 7 дней
  или без срока. «У кого» — из заголовка/assignee; «что проверить» — из описания/AC;
  «how-to-demo» — если в AC/описании есть сценарий проверки (что показать, где
  посмотреть) — привести кратко; нет — «—».
- **Риски по OKR** — `okr-kind:risk`, открытые, сгруппировать по `okr-kr:<id>`
  (заголовок KR — из списка `okr`); без привязки — группа «без KR». Владелец —
  `assignees`; пусто → `[без владельца]`. Приоритет — как в задаче.
- **Статус по командам** — истории `type: story` открытые + закрытые после прошлого
  отчёта, группировка по `team:<имя>`. «Сделано с прошлого отчёта» — изменение
  статуса/`sprint-result`/новые комментарии `[Факт]` относительно строки той же
  истории в прошлом отчёте; «осталось» — последний `[След. шаг]` или незакрытые AC.
  **Историй нет** → одна строка `[НЕТ ДАННЫХ: истории спринта в Backlog.md не
  заведены]` и сводка из последнего отчёта спринта: команда, спринт, дата, «Итог»,
  до 3 рисков — с путём к файлу. Прошлого отчёта нет → столбец «с прошлого отчёта»
  = «первый отчёт».
- **Календарь** — вывод `today.py`. Код выхода 1 → блок
  `[НЕТ ДАННЫХ: календарь — <первая строка stderr>]`, без догадок.

## Шаг 3 — отчёт

Стиль: caveman ultra + anti-slop (обе секции уже в системном промпте харнесса; здесь —
что это значит для отчёта). Каждая строка = факт с якорем (id, путь, время). Нет
факта — нет строки. Проза запрещена везде, кроме «Выводов», и там — одна строка на
вывод. Заголовок KR/цели пишется один раз, дальше только id. Пояснения в скобках —
до 5 слов. Ни вводных, ни итогов, ни переходов между блоками.

Заголовки и порядок — ровно эти: слайды рендерятся из них. Пустой блок — «нет».
Строка `KPI:` — четыре числа для титульного слайда, ровно в этом порядке.

```
# Утро {today}
KPI: просрочено {n} · сегодня {m} · рисков без владельца {r} · закрыто вчера {d}

## Ретро {yesterday} — план {p} / сделано {s} / перенесено {t} / сорвано {f}
- PO-105 · смета за август отправлена Бордюгу
- заведены 5 инициатив: цифровой рубль, VTB.PAY, БП-схемы (PO-128…132)
- созвонов: 2 (VK: переезд виджета; смета за август)
(в слайдах этот раздел — виджеты Activity/Tasks из retro.json; список здесь — для чата)

## Сегодня
### Созвоны
| Время | С кем | Повестка |
|---|---|---|
| 11:00–11:30 | Бордюг, Юмшанов | смета, вебхук |
(или одна строка: [НЕТ ДАННЫХ: календарь — <причина из stderr>])
### Задачи
| Задача | Кому · что | KR |
|---|---|---|
| PO-99 сетевая доступность GDS · −1 д | назначить исполнителя | — |
| PO-105 смета за август | Бордюг · отправить смету | PO-78 |

## Ближайшие договорённости
| Договорённость | У кого | Проверить | How-to-demo | Срок |
|---|---|---|---|---|
| PO-117 баг виджета Музыки | — | GDSLV-1897 закрыт? | — | 16.09 |

## Риски по OKR
**PO-78 [RESEARCH] замена Live-виджета на TL — 6, без владельца: 6**
| Риск | Приоритет | Владелец |
|---|---|---|
| PO-112 вебхук ломает CJM VK | HIGH | — |
**без KR — 0**

## Статус по командам
| Команда | История | Статус | С прошлого отчёта | Осталось |
|---|---|---|---|---|
| Live | PO-133 переключение 50/50 | In Progress | [Факт] 50% | мониторинг |
(или: [НЕТ ДАННЫХ: историй type: story нет], строка
`GROUND/RESULTS/<file> · <команда> · <спринт> · <итог числами>` и таблица
| Стрим | Статус | из рисков отчёта спринта, до 3 строк)

## Нужны решения
- PO-99, PO-103 — закрыть, перенести или эскалировать?
- владелец рисков по PO-78 — кто?
Прочее: задач {n} · договорённостей {m} · БФТ открытых {k}
```

Лимиты: «Задачи» ≤ 7 строк, просроченные первыми с `· −N д` в ячейке задачи,
остальное числом в «Прочее». Ретро ≤ 8 строк, по одной на задачу/событие. «Нужны решения» ≤ 5 — только то,
что требует ответа PO или руководителя. Заголовок KR — один раз. Заголовки задач в
таблицах — до 6 слов. Числа — реальные счётчики. После строки «Прочее» ничего нет.

## Шаг 4 — сохранить, отрисовать, STOP

1. Записать отчёт в `GROUND/PULSE/morning/{today}.md` с frontmatter:

```yaml
---
type: morning-report
date: {today}
prev_report: {prev или null}
sources: [backlog.md, calendar|none, GROUND/RESULTS/<sprint-report>|none]
---
```

2. Записать данные слайда ретро в `GROUND/PULSE/morning/{today}.retro.json` —
   из них рендерер собирает виджеты Activity/Tasks, панель карточки и заметку
   «Описать ретро»:

```json
{
  "date": "{yesterday}",
  "note_draft": "Ретро {yesterday}\n## Что было сделано\n- [x] … (PO-…)\n\n## Как это влияет на цели спринта\n- …\n\n## Как это влияет на цели квартала\n- …\n\n## Что не получилось сделать\n- [ ] … (PO-…)\n",
  "activity": [{"start": "11:00", "end": "11:30", "with": ["…"],
                "note": "VK: переезд виджета\n## Итог\n- …\n\n## Решения\n- [ ] … (PO-…)\n\n## Источники\n- календарь MTS Exchange, событие {yesterday} 11:00 (tools/calendar-today)\n- повестка события: «…»\n"}],
  "tasks": [{"id": "PO-105", "kr": "PO-78", "priority": "high", "due": "2026-09-11", "done_at": "{yesterday}",
             "note": "Ишманов + Бордюг: отправить смету за август\nСделано: …\n\n- [x] …\n- [ ] …\n\n## Источники\n- Backlog.md: backlog/tasks/po-105, status Done, updatedAt {yesterday}\n"},
            {"note": "Заведены 5 инициатив: …\n1. PO-128 …\n2. PO-129…132 …\n\n- [ ] привязать к KR\n\n## Источники\n- Backlog.md: backlog task list --json, createdAt {yesterday} (PO-128…PO-132)\n"}]
}
```

   Правила:
   - **Заметка — единственное содержимое строки.** Первая строка `note` — название
     (любой длины, без `#`), дальше блоки: заголовки `##`, списки `-`/`1.`, чеклисты
     `- [ ]`/`- [x]`, цитаты `>`, разделитель `---`. Inline-разметка (`**`, `` ` ``) в
     редакторе не рисуется — не использовать.
   - **Раздел `## Источники` обязателен** в каждой заметке `tasks` и `activity`:
     откуда сведения — путь к файлу задачи и поле, команда и поле `--json`, событие
     календаря, заметка PULSE. Без него рендерер отказывает (код 1).
   - `priority`, `due`, `done_at` (задачи), `start`/`end` (события) — в шапку панели:
     чек, дата («Вчера»/«Сегодня»/ДД.ММ), флаг приоритета. Нет данных — поле опускается.
   - **Всё сделанное за вчера — строки `tasks`.** С `id`, если это задача Backlog.md
     (`Done`/`Cancelled`, `updatedAt` = вчера); без `id` — результаты-абстракции
     («Заведены 5 инициатив», «Фикс вебхука») с источниками на реальные записи.
   - `activity` — события `today.py --date $yesterday --json`; заметка: название
     встречи, «## Итог», «## Решения» — только из повестки/описания события и заметок
     PULSE; нет данных — только название и источники. Код 1 у календаря → `[]`.
   - `note_draft` — заметка ретро: первая строка `Ретро {yesterday}`, затем ровно
     четыре раздела: «Что было сделано», «Как это влияет на цели спринта», «Как это
     влияет на цели квартала», «Что не получилось сделать». Наполнение — только из
     `tasks`/`activity` и Backlog.md (KR, milestone); нет данных под раздел — раздел
     пустой. Пусто всё → `""`, рендерер подставит пустую заготовку. Не додумывать.

3. Записать данные слайда «Сегодня» в `GROUND/PULSE/morning/{today}.today.json` —
   виджеты Задачи/Договорённости с заметками, вкладки «План на сегодня» и «Календарь»:

```json
{
  "date": "{today}",
  "plan_draft": "План на сегодня {today}\n## Задачи\n- [ ] PO-… — кому · что\n\n## Созвоны\n- 11:00 … — что получить\n\n## Договорённости\n- [ ] PO-… — что проверить\n\n## Риски\n- …\n",
  "calendar": [{"start": "11:00", "end": "11:30", "title": "…", "with": ["…"], "organizer": "…", "agenda": "…",
                "source": "календарь MTS Exchange, событие {today} 11:00"}],
  "tasks": [{"id": "PO-105", "kr": "PO-78", "priority": "high", "due": "{today}",
             "note": "Ишманов + Бордюг: отправить смету за август\nКому: Бордюг. Что: смета за август.\n\n- [ ] отправить\n\n## Источники\n- Backlog.md: backlog/tasks/po-105, due {today}, okr-kr:PO-78\n"}],
  "controls": [{"id": "PO-117", "due": "2026-09-16",
                "note": "Подправить для Музыки баг с генерацией виджета\nУ кого: —. Проверить: GDSLV-1897 закрыт?\n\n- [ ] спросить статус\n\n## Источники\n- Backlog.md: backlog/tasks/po-117, okr-kind:control\n"}]

```

   - `tasks` — строки таблицы «Задачи» (просроченные первыми, `due` ≤ сегодня),
     `controls` — «Ближайшие договорённости»; заметка каждой — те же правила, что в
     retro.json: первая строка — название, дальше «кому · что» / «что проверить» /
     how-to-demo из AC, чеклист шагов, обязательный `## Источники`.
   - `calendar` — события `today.py --date $today --json` как есть (код 1 → `[]`);
     полный список — в панели «Календарь». Не-ритуалы помечать `"key": true` и давать
     `"goal"` («что получить») — они выходят на главный экран как «Ключевые встречи»
     с повесткой. Ритуалы (дейлики, синки) — `key: false`.
   - `plan_draft` — заметка «План на сегодня»: первая строка `План на сегодня {today}`,
     разделы «Задачи», «Созвоны», «Договорённости», «Риски» — только из `tasks`,
     `calendar`, `controls` и рисков отчёта. Пусто всё → `""`.

4. Записать `GROUND/PULSE/morning/{today}.risks.json` — слайд рисков: таблица

```json
{
  "date": "{today}", "review_draft": "",
```

   `sources` обязателен (рендерер собирает из полей заметку с разделом «Источники»).
   `review_draft` — заметка «Актуализация рисков» с разделами Новые / Изменились /


   - Источник — истории `type: story` с метками `sprint:<id>`, `team:<имя>`;
     `done`/`left`/`blockers`/`next` — из комментариев `[Факт]`, `[Блокатор]`,
     `[След. шаг]` и AC; `pulse` — комментарии спринта как есть. Нет историй →
     `"teams": []`, слайд остаётся сводкой из markdown.
   - `agreements` — договорённости с командой на спринт (`okr-kind:control` с
     `team:<имя>` или из комментариев): что · от кого · когда · кому, `done`.
   - `comment_draft` пустой → заметка «Комментарий» собирается рендерером: по каждой
     истории «Что уже сделано / Что осталось / Какие есть блокаторы / Какой следующий
     шаг». `agreements_draft` пустой → реестр-чеклист из `agreements`.

6. Отрисовать слайды — детерминированно, из markdown и json, без правок руками:

```bash
python3 <poh-morning-status>/tools/morning-slides/render.py GROUND/PULSE/morning/{today}.md
```

Пишет `GROUND/PULSE/morning/{today}.html` (один файл, без внешних библиотек), читая
рядом `{today}.retro.json`, `{today}.today.json`, `{today}.risks.json`, `{today}.teams.json`.
Код выхода 1 — markdown или json не по шаблону; починить отчёт, не рендерер.
Заметка «Описать ретро» правится в браузере и хранится в его localStorage; навык её
не читает.

7. Ответить в чат самим отчётом (markdown как есть) и одной строкой путями к `.md`
и `.html`. Остановиться.

Файлы — дневник PO, подтверждения не требуют; повторный запуск в тот же день
перезаписывает. Дальше только по явному «да» PO, по одному пункту, через
`backlog task edit` / `task_create` (`type: potask`, `okr-kind:<kind>`,
`okr-kr:<id>`, `--due`), с показом изменения до вызова. После записи — напомнить
нажать «Обновить» в «Управлении целями».

## Правки PO из «Комментарии для LLM»

Если в сообщении PO пришёл промт из экрана «Комментарии для LLM» (начинается со
«Скорректируй утренний отчёт от …», содержит блоки `## <раздел> · «<заметка>»` со
строками `-`/`+`) — это правки PO поверх прошлого отчёта. Правила:
- строки `+` PO добавил, `-` удалил, `[x]` — отметил сделанным; правки имеют приоритет
  над данными Backlog.md и календаря;
- собрать отчёт заново по шагам 1–6 на актуальных данных, затем наложить правки на те же
  заметки (по разделу и названию); правка, которой не к чему прикрепиться (задача
  закрыта, история ушла), — в «Нужны решения» строкой «правка PO без цели: …»;
- если правка противоречит данным (PO отметил сделанным, а задача открыта) — оставить
  правку и вынести расхождение в «Нужны решения»;
- формат и разделы отчёта не менять.

## Guardrails

- **Нет источника — нет факта.** Backlog.md недоступен → `[НЕТ ДАННЫХ]`, а не «спокойный день».
- **Ретро — только результаты с id.** Активность без результата и результат без задачи в Backlog.md не пишутся.
- **Не сглаживать.** Просрочка на 20 дней так и называется.
- **Не менять Backlog.md без «да».** Даже очевидное — сначала вопрос.
- **Не звать другие навыки** из отчёта.
