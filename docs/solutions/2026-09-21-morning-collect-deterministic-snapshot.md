# Сбор утреннего отчёта ~20 шагами jq заменили одним детерминированным скриптом

## Ситуация

Навык утреннего отчёта (`skills/morning/SKILL.md`, команда `/morning`) на шагах 1–2 сам собирал
и классифицировал данные: ~20 шагов вида `backlog … --json | jq …`, всего ход 24+ шагов и
~3,5 минуты. Заявленный бюджет навыка — 12–15 вызовов — нарушался вдвое. Классификация
(KPI, исход плана прошлого отчёта, риски по KR) выполнялась моделью, то есть медленно,
дорого и недетерминированно.

## Причина

Сбор и классификация — механическая работа над JSON (фильтры, группировки, счётчики), но
механика навыка была устроена так, что её делали LLM-ходы: каждая выборка — отдельный вызов
терминала с разбором вывода руками модели.

## Решение

Новый `tools/morning-collect/collect.py`: один вызов без LLM собирает и классифицирует всё
в снимок `GROUND/PULSE/morning/<дата>.data.json` — `kpi`, `retro` (исход плана прошлого
отчёта `done/moved/failed/missing`, закрыто/заведено/правлено вчера), `tasks_today/later`,
`controls_soon/later`, `risks.groups` по KR с заголовками, `details` по задачам дня и
договорённостям (не больше 20), календарь на сегодня и вчера, прошлый отчёт, отчёт спринта.
`SKILL.md` переписан: шаг 1 — вызов скрипта и чтение снимка целиком с таблицей «ключ → куда
в отчёт», шаг 2 — только смысл полей, ничего не пересчитывать; бюджет снижен до 4–6 вызовов.
Источники — ровно те, что разрешены навыку; даты закрытия приводятся к МСК; недоступный
календарь — не ошибка, а `ok:false` с причиной. Код выхода 1 — только когда недоступен
Backlog.md, без него отчёта нет.

## Как проверить

`python3 -m unittest discover -s tools/morning-collect/test` — 9 тестов (классификация,
МСК-даты, парсер прошлого отчёта, CLI вне воркспейса). На реальном воркспейсе из 179 задач:
6 секунд, снимок 32 КБ, счётчики совпали один в один с ручным разбором модели из
прерванной сессии.

## Уроки

Механическую обработку JSON в навыке надо уводить из LLM-ходов в скрипт при первых
признаках: счёт шагов только на сбор перевалил за десять, повторяющиеся цепочки jq, перерасход
бюджета вызовов. Снимок «данные отдельно — текст отдельно» заодно даёт кэш на случай
обрыва и проверяемость счётчиков тестами.
