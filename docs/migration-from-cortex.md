# Миграция коннектора MTS.Link из ishmanov-cortex

Статус: коннектор перенесён, предшественник ещё на месте. Документ фиксирует найденный
дефект, различия и порядок вывода старого инструмента из эксплуатации.

## Найденный дефект

`ishmanov-cortex/tools/mts-link-chat-sync` на этой машине **нерабочий, но об этом не
сообщает**.

Проверка:

```
$ cd ishmanov-cortex/tools/mts-link-chat-sync
$ node chats.mjs --list-watched
Реестр пуст. Сначала добавь чаты: --list-chats → --add (см. README).
$ echo $?
0
```

Реестр при этом не пуст — в волте лежит `GROUND/_intake/chats/watched-chats.yaml` с
записью «Продуктовый штаб Ticketland».

### Причина

`config.mjs` резолвил `OUTPUT_DIR` из `.env`, а при его отсутствии молча брал дефолт
`./chats-out` внутри самой папки инструмента. Файл `.env` отсутствует (он gitignored и на
эту машину не переносился), поэтому:

1. Инструмент искал реестр по пути `tools/mts-link-chat-sync/chats-out/watched-chats.yaml`.
2. Не нашёл, сообщил «реестр пуст» и вышел с кодом 0.
3. Побочно создал пустую папку `chats-out/` (удалена при проверке).

Сообщение «реестр пуст» неотличимо от «ты смотришь не в ту директорию». Ни один код
возврата не сигнализировал о проблеме.

### Почему это критично именно для брифа

Для ручного разбора чатов дефект терпим: PO видит пустой список, удивляется, разбирается.
Для автоматического утреннего брифа это худший из отказов — `/morning` отчитается о
спокойном вчерашнем дне в день, когда всё горело. Молчаливый ноль хуже громкой ошибки:
он выглядит как валидный результат.

Сопутствующее расхождение: `.env.example` называет дефолтом сессии
`~/.mts-link-chat-sync/auth.json`, а `/chat-sync` в SKILL.md ссылается на
`~/.mts-link-sync/auth.json`. На машине существуют оба файла, разного возраста
(17 августа и 13 июля). Актуален первый.

## Что сделано в преемнике

| Изменение | Причина |
|---|---|
| `MTS_LINK_OUTPUT_DIR` обязателен, дефолта нет | устраняет корень дефекта |
| Режим `--status`, код выхода 1 при проблемах | расхождение конфигурации видно до выгрузки, а не после пустого результата |
| Префикс `MTS_LINK_*` вместо `CHAT_SYNC_*` | инструмент больше не только про чаты; исключает подхват старых переменных |
| Дельта-курсор `.sync-cursor.json` | бриф отвечает «что изменилось», а не «что существует» |
| Режимы `--since-last`, `--yesterday` | суточная гранулярность брифа |
| Поле `incremental` во frontmatter | разбор видит, полное это окно или дельта |
| 22 теста без сети | курсор и границы окна ломаются молча |

Совместимость сохранена: формат `watched-chats.yaml` и формат дампов не изменились,
существующий реестр и 149 выгруженных файлов работают как есть.

## Порядок вывода предшественника

Не выполнено — требует решения PO.

1. Прогнать `--pull --since-last` преемником, убедиться, что дампы и курсор пишутся в волт.
2. Сверить вывод с последней выгрузкой старого инструмента (`2026-07-14..2026-07-29`).
3. Переключить скиллы `/chat-sync` и `/chat-watch` в `ishmanov-cortex/.claude/skills/` на
   новый путь и команды.
4. Удалить `ishmanov-cortex/tools/mts-link-chat-sync`, оставив в README волта ссылку сюда.

До шага 3 в волте живут два инструмента с пересекающейся ответственностью. Это осознанный
временный компромисс: скиллы `/chat-sync`, `/link-radar` и `/daily-review` завязаны на
старые пути, и их переключение — отдельная работа со своей проверкой.

## Не проверено

Сетевые режимы (`--list-chats`, `--pull`) вживую не запускались: требуется корпоративный
VPN и действующая SSO-сессия. Проверены офлайн-режимы, чистые модули и совместимость с
реальным реестром волта. Первый сетевой прогон — за PO.
